# Лабораторна робота №3 — Каталог нерухомості

Вебзастосунок для перегляду та пошуку оголошень про продаж нерухомості.

## Інформація про роботу

- **Тема:** каталог нерухомості.
- **Варіант:** 3 — продаж нерухомості.
- **Технології:** Laravel 13, PHP, MySQL 8.4, Docker Compose, Blade, Eloquent ORM.
- **Автор:** Дячко Діана Євгенівна.
- **Група:** 6.1224.

## Вимоги

- Перегляд рекомендованих оголошень на головній сторінці.
- Перегляд каталогу та окремого оголошення.
- Пошук за назвою та коротким описом.
- Фільтрація за категорією й операцією.
- Сортування за датою публікації та ціною.
- Пагінація з вибором кількості записів на сторінці.
- REST API з JSON-відповідями та валідацією параметрів.
- Зберігання категорій і оголошень у MySQL через Eloquent ORM.

## Запуск застосунку

Переконайтеся, що Docker Desktop запущено. У кореневій папці проєкту виконайте:

```powershell
docker compose up -d --build
```

Вебзастосунок доступний за адресою:

http://localhost:8080

Перевірка стану контейнерів:

```powershell
docker compose ps
```

Перегляд журналів:

```powershell
docker compose logs -f app
```

## База даних

- СУБД: MySQL 8.4.
- Назва бази даних: `web_catalog`.
- Таблиці основних сутностей: `categories`, `products`.
- Дані зберігаються у Docker volume.

Під час первинного налаштування нового середовища, після перевірки конфігурації `.env`, можна виконати:

```powershell
docker compose exec app php artisan migrate --seed
```

**Увага:** не запускайте цю команду в наявному середовищі без потреби. Перед повторним заповненням бази перевірте реалізацію міграцій і сідування. Не використовуйте `migrate:fresh`, оскільки ця команда видаляє наявні таблиці.

Приклад сторінки оголошення:

`/catalog/dilianka-dlia-pryvatnoho-budynku`

## REST API

Усі адреси API починаються з `/api`.

| Метод | URL | Призначення |
|---|---|---|
| GET | `/api/catalog` | Список оголошень із пагінацією |
| GET | `/api/catalog/{slug}` | Одне оголошення за slug |

### Параметри каталогу

- `q` — пошуковий запит.
- `category` — назва категорії.
- `operation` — операція, наприклад `Продаж`.
- `sort` — `newest`, `price_asc` або `price_desc`.
- `page` — номер сторінки, починаючи з 1.
- `per_page` — кількість записів: 9, 12 або 24.

Приклад запиту:

```text
http://localhost:8080/api/catalog?sort=price_asc&per_page=9&page=1
```

Приклад пошуку:

```text
http://localhost:8080/api/catalog?q=будинок
```

### Коди відповідей

- `200 OK` — успішний запит.
- `404 Not Found` — оголошення не знайдено.
- `422 Unprocessable Entity` — помилка валідації параметрів.

Для отримання JSON-помилок валідації передавайте заголовок:

```text
Accept: application/json
```

## Тестування API

Колекція Postman зберігається у файлі:

`postman/lab3.postman_collection.json`

Після імпорту колекції в Postman задайте змінну `base_url` зі значенням:

`http://localhost:8080`

Перевірте список оголошень, пошук, фільтри, сортування, пагінацію, перегляд окремого оголошення, відповіді `404` і помилки валідації `422`.

## Зупинка застосунку

Щоб зупинити контейнери без видалення даних бази:

```powershell
docker compose stop
```

Не використовуйте `docker compose down -v`, якщо потрібно зберегти дані у Docker volume.
